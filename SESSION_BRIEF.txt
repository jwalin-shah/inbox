## What this repo does

Local FastAPI server + TUI unifying iMessage, Gmail, Google Calendar, Sheets, Docs, Drive, Notes, Reminders, and GitHub. Agents access via HTTP API or MCP. Canonical **personal-data gateway** for the Master Orchestrator — not a replacement for orchestrator queue/routing or Odysseus operator UI.

Primary validation:
  scripts/validate_agent_safe.sh
  scripts/check_tooling.sh
  uv run pytest tests/ -q --no-cov

Server (daily driver): port 9849. Dev worktrees use 9850+ via `dev.sh`.

## Context firewall (mandatory)

- Treat `tokens/`, `credentials.json`, `github_token.txt`, and macOS message/contact DB paths as **HIGH ISOLATION** — personal PII.
- Do not mix inbox message bodies, contact graphs, or OAuth tokens into cross-project memory, training corpora, or client datasets (e.g. BTW).
- Orchestrator workers on `project=inbox` must receive project-scoped memory only (`context_pack` filters by project).
- Stay inside `~/projects/inbox/` unless the task explicitly requires orchestrator coordination files (`orchestrator-mvp/data/portfolio.json`).
- Never commit, print, or log secrets (`INBOX_SERVER_TOKEN`, OAuth refresh tokens, API keys).
- Writes that send messages, modify mail, or mutate calendar/reminders require explicit human approval unless the queue item authorizes bounded `INBOX_TEST_MODE=1` validation.

- Control plane stays in `orchestrator-mvp`: queue, routing, proof, provider limits, rollover, memjuice/CocoIndex.

- Project card: `.orch-context.json` — isolation posture, validation commands, hook inheritance.
- MCP variants: `mcp_server.py`, `inbox_mcp_stdio.py`, `inbox_mcp_readonly.py` (point agents at `INBOX_SERVER_URL`).
